Reports integers used as a different kind of value than the KaM Remake API expects. Unit IDs, house IDs, group IDs, hand (player) indexes, X and Y coordinates, integer type ids of the old API and tick counts are all plain Integer for the game, but the plugin knows what every API parameter and result means and follows the values into your variables, record fields, array elements, parameters and function results.

Reported, each rule separately switchable:

  • an argument of one kind passed where another is expected (Actions.HouseDestroy(UnitID, ...)), including X and Y swapped;
  • an assignment of one kind to a variable of another, and variables that receive several different kinds;
  • an integer literal where a unit, house or group ID is expected (-1 is always allowed);
  • arithmetic (+ - * div mod Inc Dec) on ids, ordering comparisons (<, >) between ids, comparisons between different kinds;
  • an integer type id passed to a function that has an ...Ex variant taking TKMUnitType and friends.

Kinds of your own declarations are inferred from what is assigned to them, from event handler signatures (the parameters of OnHouseBuilt are house IDs) or written explicitly: // @kind unitId above a variable, // @kind aParam unitId above a routine for a parameter, // @kind none to switch inference off for a declaration. An expression can be annotated too: {@kind houseId} above an assignment names the kind of the assigned value, and the same comment directly in front of an argument or operand names that expression's kind. Nothing is reported while a kind is unknown; an explicit Integer(x) cast removes a kind.

Elements of an array indexed by constants (Attack[ATTACKER_ID_] := ...) keep their own kinds, also after the array is stored in another array or passed to a routine. An element read through a computed index from an array whose elements differ is unknown and never reported.
